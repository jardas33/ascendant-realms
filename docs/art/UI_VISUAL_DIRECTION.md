# UI visual direction

The UI should feel like a readable field instrument: clear hierarchy, stable safe-area anchors, restrained ornament, high-contrast text, and concise state language. A selected card should answer what is selected, what it is doing, what it can do, and why an action is disabled.

Normal player mode must not depend on debug/proof prose. Debug overlays may exist behind an explicit review mode and must not leak into normal captures.
