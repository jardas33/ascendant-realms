# Quality bar

This is a review rubric, not a release claim. A lane passes only when normal player evidence supports the claim at gameplay scale.

| Dimension | Pass condition |
| --- | --- |
| Boot and identity | The intended game, map, faction, difficulty, and objective agree from setup through runtime. |
| Interaction | A player can select, command, build, train, and understand the result without debug labels or hidden test hooks. |
| Navigation | Orders produce visible, causal, reliable movement on ordinary walkable terrain and fail clearly when blocked. |
| Combat | Targeting, damage, health, casualty, destruction, and result flow are legible in a deterministic scenario and a natural match. |
| Economy | Costs, income, workers, queues, and disabled reasons are visible and consistent. |
| Presentation | Units, buildings, roads, terrain, ownership, health, and effects separate at realistic zoom. |
| Results | Victory/defeat, rewards, Continue, replay, and Play Again form a truthful, recoverable flow. |
| Resilience | 1920x1080 and 1366x768 preserve safe areas, text, buttons, and camera bounds. |
| Evidence | Captures are fresh, normal-scale, correctly labeled, non-black, and tied to the actual runtime state. |

If one dimension fails, record the failure and scope the next repair. Do not compensate with a title card, stale screenshot, or a larger validator report.
